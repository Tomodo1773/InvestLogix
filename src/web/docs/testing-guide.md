# テストコード作成ガイド (Web)

このドキュメントは、フロントエンド（React/TypeScript）のテストコードを作成する際の参考情報を提供します。

## テストの実装方針

### 基本原則

- カバレッジだけを追い求めず、開発者が認知・管理できる範囲に留める
- 正常系を中心にテストを実装
- 異常系は必要最低限のものに限定
- 1人開発のため、過度な品質は追求しない
- 外部リソース中心でモック中心になるテストは見送る

### テスト環境

- **Vitest**: Viteベースプロジェクトに最適なテストフレームワーク
- **@testing-library/react**: Reactコンポーネントテスト
- **@testing-library/user-event**: ユーザーインタラクションテスト
- **msw**: APIモック（必要に応じて）

### テスト優先度

#### 優先度：高
純粋関数や再利用性の高いロジックを優先。テストしやすく、バグの影響範囲が大きい部分。

- ユーティリティ関数 (`lib/format.ts`, `lib/utils.ts`)
- カスタムフック (`lib/hooks/`)
- グラフロジック（データ変換関数）
- 状態管理 (`lib/stores/`)

#### 優先度：中
UIコンポーネントのテスト。ユーザー体験に直接影響するが、モックが必要になる場合がある。

- テーブルコンポーネント
- サマリーカード
- チャートコンポーネント
- フォームコンポーネント

#### 優先度：低
統合テストやE2Eテストでカバーする方が効率的な部分。

- ページコンポーネント (`routes/`)
- レイアウトコンポーネント
- 認証プロバイダー

### 見送っているテスト

以下は実装コストに対してテスト価値が低い、または他のテストでカバーされるため見送り。

- **APIクライアント** (`lib/api/client.ts`): 外部API呼び出しが中心。ほぼモックになるため価値が薄い
- **shadcn/ui コンポーネント** (`components/ui/`): サードパーティライブラリのコンポーネント。ライブラリ側でテスト済み
- **Recharts グラフ描画**: グラフライブラリ自体の動作テストは不要。データ加工ロジックのテストでカバー

## 参考資料

- テストファイルは実装ファイルと同じディレクトリに配置し、`.test.ts` または `.test.tsx` の拡張子を使用する
- テストは読みやすく、メンテナンスしやすいコードを心がける
- 過度なモックは避け、実際の動作に近い形でテストする
- `src/web/docs/TEST_LIST.md` を参照して、どのテストが実装済みか、どのテストが必要かを確認する
- テストを実装したら、`src/web/docs/TEST_LIST.md` を適宜更新する
