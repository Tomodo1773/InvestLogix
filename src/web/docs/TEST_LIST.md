# テストリスト

本ドキュメントは、InvestLogixフロントエンドアプリケーションで実装すべきテストをリスト化したものです。

## テスト方針

- カバレッジだけを追い求めず、開発者が認知・管理できる範囲に留める
- 正常系を中心にテストを実装
- 異常系は必要最低限のものに限定
- 1人開発のため、過度な品質は追求しない
- 外部リソース中心でモック中心になるテストは見送る

---

## 推奨テスト環境

- **Vitest**: Viteベースプロジェクトに最適なテストフレームワーク
- **@testing-library/react**: Reactコンポーネントテスト
- **@testing-library/user-event**: ユーザーインタラクションテスト
- **msw**: APIモック（必要に応じて）

---

## 優先度：高

純粋関数や再利用性の高いロジックを優先。テストしやすく、バグの影響範囲が大きい部分。

### ユーティリティ関数 (`lib/format.ts`)

#### `formatCurrency`

- [x] 正の数を正しくフォーマットできる（例: `1234.5` → `¥1,235` / `$1,234.50`）
- [x] 負の数を正しくフォーマットできる
- [x] 文字列の数値を正しく処理できる
- [x] NaN の場合は `￥0` (または `$0`) を返す
- [x] JPY と USD で小数点以下の桁数が異なることを確認

#### `formatPercent`

- [x] 正の数に `+` 符号が付与される（例: `5` → `+5.00%`）
- [x] 負の数は `-` 符号のまま表示される
- [x] 文字列の数値を正しく処理できる
- [x] null/undefined の場合は `0.0%` を返す
- [x] 0 の場合も `+` 符号が付与される

#### `formatYearMonth`

- [x] 年月を正しくフォーマットできる（例: `2024, 1` → `2024/01`）
- [x] 月のゼロパディングありで表示される

#### `formatDate`

- [x] ISO形式の日付文字列を `YYYY/MM/DD` 形式に変換できる
- [x] タイムスタンプ付き日付を正しく処理できる
- [x] 無効な日付文字列の場合は空文字列を返す

### ユーティリティ関数 (`lib/utils.ts`)

#### `cn` (classnames結合)

- [x] 複数のクラス名を結合できる
- [x] 条件付きクラス名を正しく処理できる
- [x] Tailwindの競合するクラスを正しくマージできる（例: `p-2 p-4` → `p-4`）

### カスタムフック (`lib/hooks/use-pagination.ts`)

#### `usePagination`

- [x] データを正しくページ分割できる
- [x] `currentPage` が初期値 `1` であること
- [x] `totalPages` が正しく計算されること
- [x] `paginatedData` が現在ページのデータのみを含むこと
- [x] `handlePageChange` でページを切り替えられること
- [x] `hasNextPage` / `hasPreviousPage` が正しく判定されること
- [x] データが undefined の場合に空配列を返すこと
- [x] ページ範囲外へのアクセスを防止できること

### グラフロジック (`components/dashboard/asset-chart.tsx`)

#### `filterDataByTimeFrame`

- [x] `daily` で全てのデータを返す
- [x] `monthly` で月ごとの最後のデータポイントを抽出できる
- [x] `yearly` で年ごとの最後のデータポイントを抽出できる
- [x] 空配列が渡された場合に空配列を返す

### 状態管理 (`lib/stores/auth-store.ts`)

#### `useAuthStore`

- [x] 初期状態で `isAuthenticated` が `false` であること
- [x] `setUser` でユーザーを設定すると `isAuthenticated` が `true` になること
- [x] `logout` で状態がリセットされること
- [x] `setLoading` でローディング状態を切り替えられること

## 見送っているテスト

以下は実装コストに対してテスト価値が低い、または他のテストでカバーされるため見送り。

### APIクライアント (`lib/api/client.ts`)

外部API呼び出しが中心。ほぼモックになるため価値が薄い。
実際の動作確認は開発時の手動テストまたはE2Eテストでカバー。

- `login()` - 認証API呼び出し
- `getCurrentUser()` - ユーザー情報取得
- `getPortfolioSummary()` - ポートフォリオサマリー取得
- `getPortfolioHistory()` - 資産推移取得
- `getHoldings()` - 保有銘柄取得
- `getTransactions()` - 取引履歴取得
- `getDividends()` - 配当履歴取得
- その他のAPI関数

### shadcn/ui コンポーネント (`components/ui/`)

サードパーティライブラリのコンポーネントをそのまま使用。
ライブラリ側でテスト済みのため、アプリケーション側でのテストは不要。

- `Button`, `Card`, `Table`, `Tabs` など

### Recharts グラフ描画

グラフライブラリ自体の動作テストは不要。
データの加工ロジック（`filterDataByTimeFrame` など）のテストでカバー。

1. **フェーズ1**: 優先度「高」のユーティリティ関数とカスタムフックのテストを実装
2. **フェーズ2**: 優先度「中」のテーブル・フォームコンポーネントのテストを実装
3. **フェーズ3**: 必要に応じて統合テストやE2Eテストを検討
